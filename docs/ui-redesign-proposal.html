VIDEOSHELL · UI 2.0 DESIGN PROPOSAL

视频壳 界面设计方案
玻璃浮岛 2.0 —— 习惯延续，质感升维

这不是一次推倒重来。现有界面最值钱的资产是三样：三 Tab 信息架构、磨砂玻璃浮岛材质、 「输入网址就能看」的心智模型。方案 2.0 在此之上做一致性收敛 + 主次重构 + 状态语言统一， 让每一次触摸都落在用户已经熟悉的位置上。

Android · minSdk 21 Material Components 亮 / 暗双主题 WCAG AA 2026-09-23 · v1 草案

01设计上下文

设计判断的依据 —— 先说清楚"为谁、在什么场景、解决什么"。

维度内容
目标用户安卓用户（含开发者本人长期自用）。不是极客，也不需要被教育 —— 打开 App 的唯一目的：找到源、点开、看片。
核心任务① 粘贴/输入网址 → 识别站型 → 浏览观看（低频但关键）；② 在已知站源内浏览分类、搜索、点开播放（高频）；③ 历史续播（高频，最被依赖的路径）。
气质定位克制的光学仪器：玻璃浮岛是 App 的识别符号，负责"美"；信息层级与状态反馈负责"易用"。两者不冲突 —— 玻璃之下必须是清晰的内容。
硬约束包体敏感（R8 后 3.05MB，不引入新 UI 库）；单手竖屏为主；暗色为默认主题；列表必须从导航栏玻璃下穿过（v1.0.49 确立的物理规则）。

02现状诊断

逐条对照现有布局（activity_main.xml / dimens / colors）得出，每条都指向一个可落地的改法。

判定问题细节
待改进站源页动作过多、主次不分输入框 + 2 个等权按钮（检测/嗅探）+ 2 个文字按钮（直接播放/网页浏览）+ 4 个管理按钮并排 —— 首屏 8 个可点击元素竞争注意力，新用户不知道先按哪个。核心动作「添加站源」反而没有视觉主角。
待改进状态反馈各自为政tvHint / tvHomeState / tvUpdateHint / tvEmpty 四处裸 TextView，字号 12–13sp 不齐，成功/失败没有统一的视觉语言（体检徽章 ok/bad 色已有，但只用在站源列表）。
待改进「我的」页行缺图标锚点行内只有文字 + ›，扫读时没有视觉锚；行高 padding 14dp 与 48dp 输入框、44dp 按钮的节奏未对齐成一套。
待改进亮色辅助文字对比度不足text_hint #7C8797 在白底上 ≈ 3.6:1，低于 AA 的 4.5:1，而它大量用于 12sp 小字（分组标题、空态、提示）。
保持三 Tab + 底部玻璃导航v1.0.49 起"真正浮起"，卡片从玻璃下穿过 —— 这是 App 质感的核心来源，不动。
保持Token 体系已有骨架dimens.xml 的字号/间距/圆角/浮岛四套尺度、colors.xml 的玻璃四层材质已经集中管理 —— 2.0 只做补档与执行率，不换体系。
保持海报 3 列 + 1:1.4 比例搜索页左栏 76dp 反算保证两页卡片同宽 —— 精密的既有决策，沿用。

03四条设计原则

之后所有页面的取舍，都用这四条裁决。

🧭
习惯不动三 Tab 结构、底部浮岛、海报 3 列、"粘贴网址就能看"的心智全部保留。改动只发生在 Tab 内部。
🫧
玻璃一致所有浮层只用一套浮岛尺度（island_gap 10 / pad 14·10 / radius 16）与玻璃四层材质，禁止页面自创第二套半透明。
👁
可读性优先能读比更透重要（既有铁律）。玻璃上的正文一律 ≥14sp、primary 色；hint 色只用于 11–12sp 的辅助信息且提亮达标。
🎯
一屏一事每屏只有一个视觉主角：首页是海报网格、站源页是「添加岛」、播放页是画面本身。其余动作降级为文字按钮或收纳。

5.1 首页 —— 新增「玻璃顶岛」

改动：现状首页直接铺 view_site_browser，站源身份、搜索入口没有固定落点。新增一块顶岛（结构 = 现有浮岛规范）： 左侧站源名 + 站型徽章（让"自动识别"这项核心能力第一次被看见），右侧搜索、历史两个图标（热区 44dp）。 分类芯片条并入顶岛下方同材质次岛。海报网格、3 列、1:1.4、grid_gap 6dp 全部不动。

续播可视化：有进度的卡片底部加 2.5dp 品牌色进度条（利用现有 HistEntry 数据，零新存储）。这是把"最被依赖的路径"（历史续播）提前到首页的第一触点。

5.2 站源页 —— 「添加岛」主次重构

现状 8 个动作 → 收敛为 1 主 + 3 次：

层级元素处理
主角「识别并添加」主按钮（满宽、44dp、实心 brand）新增合并原「检测」；这是本页唯一实心按钮
次级网页浏览 / 直接播放 / 高级检测（含嗅探）降为文字按钮一行，保留现有行为与 id
收纳导入 / 导出 / 合并 / 体检收进列表标题右侧「管理 ⌄」弹出菜单（4 个 38dp 并排按钮退役，顺带解决热区不足）

站源行升级：站点 Logo 字符块（品牌色取自站名首字哈希）+ 状态徽章（沿用 ok/bad 色体系 + 新增「未体检」灰态）。失联站源整行 60% 透明度——状态一眼可扫。

5.3 我的 —— 图标锚点 + 状态右显

每行加 24dp 圆角图标底（brand_tint 底 + brand 图标），分组标题用 text_hint 12sp + 0.1em 字距； 开关类设置的当前值以文字右显（「开/关/跟随系统」），替代"必须看到 Switch 才知道状态"——Switch 控件保留，两者不冲突。 行高统一 52dp（= island_min_h，与底栏节奏对齐）。

5.4 播放页 —— 只做减法

浮岛顶/底栏结构与 player_panel_clearance 144dp 体系全部沿用（改行高必须同步 values-land 的既有纪律不变）。 微调两处：① 底栏工具行四项（倍速/横屏/字幕/更多）改 8.5sp 图标+文字，与主行拉开层级；② 「选集」「线路」改胶囊描边样式，替代裸文字——这两个是播放页最高频的二次操作，值得更大的可点击暗示。

06组件规范

五类高频组件，一处定义、处处引用。

按钮（唯一三个层级）
识别并添加 取消 网页浏览 ›

实心 = 每屏最多 1 个 · 描边 = 次级确认 · 文字 = 三级动作。 圆角统一 12dp（radius），高度 44dp，按压态用 glass_pressed 同款变实反馈。

分类芯片
推荐电影剧集综艺

选中 = brand 实底白字；未选中 = surface_2 底。高度 32dp，横滑。

状态徽章（统一状态语言）
正常 失联 未体检

全 App 只此一套状态色（ok/bad + 灰），站源体检、更新检查、嗅探结果、识别进度共用。 禁止再造第四种状态色。新增「未体检」灰态补齐三态语义。

空状态 / 骨架屏

空态 = 一句话 + 一个动作按钮（"还没有站源 → 去添加"），居中、text_hint。 列表加载 = 海报位置灰色圆角块（surface_2），不用转圈 ProgressBar——骨架屏让"正在来"比"在等待"感知更快。

站源行

56dp 高 · Logo 字符块 30dp（底色 = 站名哈希从 brand/teal/purple 三色池取）· 名称 14sp + 域名 11sp mono · 右侧状态徽章。整行热区 56dp ≥ 44dp ✓。

07动效规范

克制、快、无弹性 —— 玻璃是"仪器"，不是"玩具"。（悬停下方卡片可预览三种缓动）

微交互
按压 / 芯片切换 · 150–180ms
浮层进出
顶岛 / 面板 / 菜单 · 220ms ease-out-quart
页面转场
Tab 切换内容淡移 · 300ms ease-out-expo
场景规则
按钮 / 行按压glass_pressed 变实 + 无位移。玻璃按压"变实不变深"是材质物理，别加 scale 弹跳。
列表进入卡片从下方 12dp 淡入，首屏只动前 6 张，错峰 30ms。滚动中不再触发（防抖）。
状态徽章变化体检完成：灰→绿 200ms 颜色过渡，不加闪动。
尊重系统设置animator_duration_scale=0 / 无障碍"减弱动态效果"时全部动效直达终态。
