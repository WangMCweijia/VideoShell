# 真果鉴.apk 内置视频源解析与适配性评估

> 分析对象：`D:/TRAE/视频壳/真果鉴.apk`（30.9 MB）
> 分析目标：解析其内置视频源，并判断能否适配到 VideoShell（空壳视频客户端）项目。
> 方法：解包 APK → 提取 `libapp.so` / `libduanju_core.so` → 字符串逆向还原源配置与 API 形态。

## 1. APK 本质

- **Flutter 应用**：Dart 代码编译进 `lib/arm64-v8a/libapp.so`（8.4 MB），UI/路由在 Dart 侧；`assets/flutter_assets/` 为 Flutter 资源，含 media_kit 的 HLS 播放脚本。
- **核心逻辑是 Go 原生库** `lib/arm64-v8a/libduanju_core.so`（15 MB，"duanju"=短剧）。所有源客户端、请求签名、HTML/JSON 解析均在此库中（字符串中大量 Go runtime 符号 `goroutine`/`GC`/`panic` 可佐证）。
- 播放栈：ffmpeg / mpv / media_kit（HLS，`hls1.4.10.js`）。

**结论：这不是通用影视站壳，而是一款内置多个"短剧/漫画内容源"的聚合客户端。**

### API 形态（短剧专用，私有 JSON API）
- 端点：`/api/app/playlet-tab/all`、`/api/app/playlet/detail/`、`/api/app/playlet/home/tab/`、`/api/app/vid/h5/m3u8/`、`/drama/list`、`/drama/play`、`/drama/rank`、`/search_(keyword)/page`、`/category_page`、`/recommendList`
- 数据模型：**series（剧集）→ episodes（分集）→ m3u8（HLS 播放）**，竖屏短剧；含 `preview.m3u8`/`preview.mp4` 预览、`hls_key` 加密、`#EXT-X-KEY`、CloudFront 签名 URL（`CloudFront-Policy`/`CloudFront-Key-Pair-Id`/`CloudFront-Signature`）。
- 关键字段：`series_id_str`、`series_name`、`series_cover`、`episode_count`、`free_episodes`、`category_list`、`cover_url`、`playUrl`、`contentUrl`、`backup_urls`、`viewCount`/`playCount`、`sourceID`/`source_blocked`。
- 远程配置：二进制中出现 `sources.json`/`catalogs.json`/`rankings.json` 并以 `bytes=0-1023` 范围请求拉取 → 源列表可由服务端远程下发/轮换。

## 3. 技术形态（关键障碍）

1. **请求签名全部封死在 Go 原生库 `libduanju_core.so`**：
   - 抖音式设备指纹签名：`X-Argus`、`X-Ladon`、`X-Khronos`、`X-SS-Req-Ticket`、`X-SS-STUB`（`novel.snssdk.com` 即字节系，需上述签名）。
   - CloudFront 签名 URL：需服务端私钥，客户端无法伪造。
   - 会话：`huangguo-session.json` / `huangguo-session-*.tmp`，设备绑定 `device_id`/`X-Zgj-Device`。
2. **私有 JSON API，非 HTML、非 MacCMS 标准**：无 TVBox 式 spider/jar，也无 MacCMS 标准接口。
3. **源与签名可轮换**：远程 `sources.json` 下发，域名/签名策略会随服务端更新。

## 4. 与 VideoShell 的适配性判断

### VideoShell 现有契约与适配器（依据 `app/src/main/java/com/videoshell/data/site/`）
- 契约：`SiteAdapter` 抽象方法 `categories()` / `browse(typeId,page)` / `search(keyword,page)` / `detail(id)`（`SiteAdapter.kt:14-20`）。
- 适配器：`HtmlAdapter`(Jsoup 抓 HTML)、`MaccmsAdapter`/`MaccmsXmlAdapter`(MacCMS JSON/XML)、`SeedApiAdapter`、`YeguoAdapter`；工厂 `AdapterFactory` 按 加密白名单→家族自证→人工校准→采集接口→SeedRouter→FamilyRouter→HtmlAdapter 优先级选路。

### 判定
| 维度 | 结论 |
|---|---|
| 数据契约层面 | 短剧目录**勉强**可映射到 categories/browse/search/detail，但需新增"短剧"内容域（竖屏分集模型与现有影视详情不同） |
| 请求可达性 | **不可达**：签名在 Go 原生库，Kotlin 端无法在不逆向的情况下调用；CloudFront 需私钥 |
| 适配器复用 | `HtmlAdapter` 抓不到（非 HTML）；`MaccmsAdapter` 不匹配（非 MacCMS）；每个源需从零写新适配器 |
| 稳定性 | 源/签名远程轮换，逆向成果极易失效 |
| 合规 | 红果/黄豆为商业短剧平台，逆向签名抓取大概率违反 ToS 且涉版权 |

**结论：不能直接、也不推荐把该 APK 的内置源"扒"过来适配进 VideoShell。**

## 5. 务实替代路径

若要在 VideoShell 支持短剧：
1. 新增"短剧"内容域 + 一个**干净的 JSON-API 适配器**。
2. 对接**公开或用户自有、无需闭源签名**的短剧源。
3. 可借鉴本 APK 的 series/episode/m3u8 数据模型来定义 VideoShell 的短剧契约（仅借鉴模型，不逆向其签名内核）。
