# 网盘分享站适配方案（快映 / 玩偶 一类「• 4K」站）

> 目标：让 VideoShell 支持**网盘资源站**（快映4K、玩偶4K、木偶4K…），
> 保持现有「输入网址 → 识别 → 播放」的心智模型，**不引入 TVBox 的源/配置/JSON 站点表**，
> 网盘登录放在 App 内，而不是写在源里。
>
> 参考实现：`D:/TRAE/TVBoxOSC-pro`（spider jar 反编译 + `xiaoxiao_opt/TVBoxOSC/tvbox/api.json`）
> 本文档中的所有端点、正则、HTML 形状均为**本次实测/反编译取得**，不是推测。

---

## 0. 结论

**可以做，而且改动面比想象的小。** 三条关键判断：

1. **主接入点不在"识别站"，而在"解析播放地址"那一层。**
   任何适配器产出的 `Episode.url`，只要能被认出来是网盘分享链接，就交给新的网盘解析层。
   这样"输入网址就能用"这条主线一个字都不用改，且不认站的网盘链接（用户直接粘贴
   `https://pan.quark.cn/s/xxx`）也能播。

2. **这 12 个「• 4K」站本质是同一套 maccms 模板的镜像站，且域名会在秒级轮换。**
   实测：`xsayang.fun` 302 到 `http://43.248.128.118:12512/`；config 里同一站挂了 2~4 个域名/IP。
   ⇒ 判据**不能是域名**，必须是"形状/能力自证"，与现有 `SeedFamily`/`CryptFamily` 同一套思路。

3. **登录是硬需求，不是可选项。** 实测夸克分享链接：
   - `sharepage/token`（取 stoken）→ **匿名可调**，已实测返回 200 + stoken；
   - `sharepage/detail`（列目录）→ **匿名可调**，已实测返回 200 + 文件树；
   - **取直链 / 转存 → 必须带登录 cookie**（`/file/download`、`/save`、`acquire_dl_token`）。
   ⇒ 所以"登录放软件里"正好是这套方案成立的前提，而不是额外的豪华功能。

## 2. 目标 / 非目标

| | 内容 |
|---|---|
| **要做** | 输入网盘分享站网址 → 分类/搜索/详情可用；详情页线路 = 网盘类型（夸克/阿里/UC/…）；点集 → 直接播；网盘账号在 App 内登录/清除/看状态 |
| **要做** | 直接粘贴一条网盘分享链接（`https://pan.quark.cn/s/xxx`）也能播 |
| **不做** | TVBox 式的 `api.json` / `ext` / 源列表导入 / spider jar 运行时 |
| **不做** | `ext.cookie` 这种把凭据塞进"源配置"的做法（夸父站那种） |
| **不做** | 站内"转存到我的网盘再管理"这类网盘客户端功能（只做播放所必需的最短链路；转存只作为 Provider 内部取直链的手段之一） |
| **暂不做** | 本地多线程代理（P2，见 §10） |

## 3. 架构：四层，全部落在现有约定内

```
┌─ ① 识别层（站） ─────────────────────────────────────────────┐
│  SiteDetector  →  AdapterFactory  →  PanShareRouter（新）     │
│  判据：形状/能力自证（与域名无关）                             │
│  命中 ⇒ PanShareAdapter；否则原样走 HtmlAdapter（零影响）      │
└──────────────────────────────────────────────────────────────┘
┌─ ② 适配层（站） ─────────────────────────────────────────────┐
│  PanShareAdapter : SiteAdapter                                │
│  detail() ⇒ groups: 每个网盘类型一条线路，episodes = 分享链接  │
└──────────────────────────────────────────────────────────────┘
┌─ ③ 网盘层（与站解耦） ───────────────────────────────────────┐
│  PanLink.parse(url)  →  PanResolver  →  PanProvider(9 种)     │
│  Episode.url 直接给分享链接也行（②可缺省）                     │
└──────────────────────────────────────────────────────────────┘
┌─ ④ 播放层 ───────────────────────────────────────────────────┐
│  MediaSource.Direct(url, headers, isHls, mimeType)            │
│  mediaClient 已共享 CookieJar → 分片请求自动带 cookie          │
└──────────────────────────────────────────────────────────────┘
```

**为什么 ③ 要独立于 ②**：站点会换、域名会轮换、站会死，但"夸克分享链接怎么变直链"这件事
不变。分开之后，站挂了不影响网盘层，网盘 API 变了只改一个 Provider。

## 4. 识别层：形状自证，不落域名

新增 `PanShareFamily`（对齐 `SeedFamily` / `CryptFamily` 的既有形态）：

**判据（全部可在一次详情页请求内判定，不额外发请求）**

| # | 判据 | 权重 |
|---|---|---|
| D1 | 详情页存在 `.module-tab-item.downtab-item [data-dropdown-value]` | 必需 |
| D2 | 详情页存在 ≥1 个 `[data-clipboard-text]`，且其值能被 `PanLink.parse` 认出来 | 必需 |
| D3 | `player_aaaa` 出现 0 次（区别于 maccms 站） | 加分 |
| D4 | `.module-item` 卡片 + `.module-tab-item.tab-item[data-id]` 分类形状 | 加分 |

D1 + D2 同时命中 ⇒ 判定为「网盘分享站族」。

**判定结果落盘（命中与否定都落）**，每个 host 只探一次 —— 与 `CryptFamily` 完全一致。
**绝不能写成域名白名单**：§1.2 已经证明同一站会在 `xsayang.fun` / `43.248.128.118:12512` /
`38.76.197.172:12521` 之间轮换。

**与现有链路的关系**：这一步是**新增的延迟路由**，与 `SeedRouter` 同级。
不命中就原样交给现有链路 —— 对非网盘站**零额外请求、零行为变化**。

## 5. 适配层：`PanShareAdapter`

复用现有 `HtmlAdapter` 的列表/分类抠取能力（这站是标准 maccms 模板，卡片形状 `HtmlExtractor` 已覆盖），
**只需要新增/覆盖两件事**：

### 5.1 `detail(id)` —— 从"集数列表"改成"网盘线路列表"

```
输入 详情页 HTML
线路名  取 .downtab-item [data-dropdown-value]        → "百度" / "夸克网盘"（按序、保留重复）
分享链接 取 .module-row-one [data-clipboard-text]      （按出现顺序、**按值去重**，与线路名对齐）
```

> 实现落在 `data/site/PanShareExtract.kt`（纯 DOM、可离线喂样本断言）。
> 实测样本与断言见 `tools/verify/samples/panshare/{ky,wg}_detail.html` + 套件 `runpanlink`。

产出映射到现有模型：
```kotlin
VideoDetail(groups = listOf(
    PlayGroup("夸克网盘", listOf(Episode("夸克网盘", "https://pan.quark.cn/s/30efda9bb93b"))),
    PlayGroup("阿里云盘", listOf(Episode("阿里云盘", "https://www.alipan.com/s/bwXSZMNHxMb"))),
))
```

**为什么把"展开成 N 集"推迟到解析时做**：分享链接指向的是一个**文件夹**（实测：`is_owner:0`
且返回 `dir:true` 的目录项）。展开需要调网盘接口，放在 `detail()` 里会让"进详情页"变慢且
失败就整页空。放到点了某一集之后 ⇒ 失败只影响那一集，且那时正好也在 IO 协程里。

> ⚠️ **落地时改掉了这一条**（v1.0.65 实测）：展开**放在详情页做**。理由是上面那两个顾虑
> 用别的方式都解决了，而"只列到一条线路名"的代价太大：
> 1. **列目录匿名可用**（`sharepage/token` + `sharepage/detail` 都不需要登录）⇒ 不涉及凭据，
>    也就不存在"进详情页就要登录"的体验问题；
> 2. 实测快映那条分享展开出 **55 个文件**，延迟展开意味着用户点进去只能播第一个文件
>    —— 那不是视频 App 该有的样子；
> 3. "失败就整页空"由 `PanResolver.episodes()` 兜住：展开为空时**不返回空表**，留一条
>    「打开分享（未展开）」，点它时在播放链路里再试一次并给出具体原因。
> 所以 `detail()` 里 `groups` 就是**真实集数**（线路名后缀 `（N 集）`）。

### 5.2 线路命名（画质）

TVBox 的 `Config` 里为每个盘准备了"原画 / 普画 / 无限"三档画质开关。
VideoShell 侧先做**固定映射**（夸克/UC → 原画，其余按 Provider 默认），
把"画质选择"留到 §9 的「网盘账号」页做全局偏好，不做成站点级配置项。

## 6. 网盘层

### 6.1 `PanLink.kt` —— 纯函数，9 条正则直接照搬 §1.5

```kotlin
enum class PanType { ALI, QUARK, UC, CLOUD189, CLOUD123, BAIDU, XUNLEI, GUANGYA, MOBILE }

data class PanLink(val type: PanType, val id: String, val pwd: String = "")
object PanLink { fun parse(url: String): PanLink? }
```
> 纯函数、无 IO ⇒ 可直接进离线回归 harness（`tools/verify/`），与项目既有做法一致。

### 6.2 `PanProvider` —— 统一契约

```kotlin
interface PanProvider {
    val type: PanType
    fun credential(): Credential?              // null = 未登录
    suspend fun check(): DriveState            // 未登录 / 有效 / 已过期
    suspend fun list(link: PanLink, dirId: String?): List<PanFile>
    suspend fun stream(file: PanFile): PanStream   // url + headers + 是否 HLS
}
data class PanFile(val id: String, val name: String, val isDir: Boolean, val size: Long)
data class PanStream(val url: String, val headers: Map<String, String>, val hls: Boolean, val mime: String?)
```

### 6.3 各 Provider 的接口面（实测来源见 §1）

| Provider | 入口 | 取流方式 | 登录物 |
|---|---|---|---|
| **夸克** (P0) | `drive-pc.quark.cn/1/clouddrive/**` | `share/sharepage/token` → `detail` →（`save` + `task` 轮询转存，或 `chat/conv/file/acquire_dl_token`）→ `file/download?fid=` | Cookie（`__puus`/`__uid` 等） |
| **UC** (P0) | `pc-api.uc.cn/1/clouddrive/**` | `share/sharepage/token` → `detail` → `file/v2/play`（或 `open-api-drive.uc.cn/file?method=streaming`，需 TV Token） | Cookie + 可选 TV Token |
| **阿里** (P1) | `openapi.alipan.com/adrive/v1.0/openFile/list` | 分享 `shareId`+`sharePwd` → `getDownloadUrl` | `refresh_token`（+ `device_id`） |
| **123** (P1) | 站点 API | 分享 `shareKey` → `getDownloadInfo` | 账号密码换 token |
| **天翼 189** (P1) | 站点 API | `t/{id}` → 会话 → 直链 | 账号密码换会话 |
| **迅雷** (P1) | `pan.xunlei.com` API | `s/{id}` → 直链 | token |
| **光鸭** (P1) | `api.guangyapan.com/userres/v1/**` | `get_share_page_files_list`（**需登录**）→ `get_share_download_url` → `signedURL` | **`Authorization: Bearer`**（不是 cookie；见下方补充表） |
| **百度** (P1) | `pan.baidu.com/share/list?…&root=1&dir=/…` | `s/1{code}?pwd=` →（匿名列目录）→ `/api/sharedownload` 取 `dlink` | Cookie（`BDUSS`）+ 可选 `bdstoken` |
| **移动 139** (P2) | — | — | — |

> **百度补充实测（2026-09-26，沙箱直连，样本取自玩偶站详情页的现网分享）** —— 修正了
> 本表原先"Cookie + `bdstoken`"这一格读起来像"列目录也要登录"的印象：
>
> | 步骤 | 结论 |
> |---|---|
> | 分享页 | 匿名可取；有提取码时先 `POST /share/verify?surl=…`（`errno=0`，下发 `BDCLND` 放行票据） |
> | **根目录** | **匿名可用**：`GET /share/list?uk={share_uk}&shareid={shareid}&…&root=1&dir=/` |
> | **子目录** | **匿名可用**，但**是另一套形状**：**不带 `root`**，`dir=` 取该项的 `path` 字段
> —— 那是**拥有者侧绝对路径**（如 `/2026-YIN/出入`、`/电影/2026/X 消失-的-人呀`），
> 不是分享相对路径。实测：`root=1&dir=/` → 1 个目录；改用它自己的 `path` → **4 个 mp4 文件** |
> | `root=1` | **必需**（仅根目录），缺它一律 `errno=-21`。⚠️ 但它会**静默忽略 `dir`**：
> 给子目录带 `root=1` 会**返回根目录的内容**，看起来"下钻成功"其实原地打转（见 PITFALLS §4.80） |
> | `dlink` | ⛔ **匿名不成立**。实测：`/api/sharedownload`（页内 `sign` 匿名抠不到）→
> `errno=113 验证码签名错误`；`/share/download` → `errno=112`。⇒ 取流要登录态，

### 6.4 缓存纪律（这一条不能破）

| 缓存对象 | 允许 | 理由 |
|---|---|---|
| 分享 `stoken` | ✅（TTL 到 `expired_at`） | 匿名可得，与用户登录态无关 |
| 目录树 `fid → name` | ✅（进程内，10 min） | 稳定 |
| **直链** | ❌ **绝不落盘** | 带时效签名/一次性 token，落盘必然"昨天能播今天不能" |

这条与项目既有纪律一致：`PlayerShell` / 播放令牌从来只当次取用。
另外 `ListCache` 只缓存分类首屏，天然不涉及直链。

### 7.2 两类凭据的获取方式

| 类型 | 网盘 | 方式 |
|---|---|---|
| **Cookie 类** | 夸克、UC、百度 | 内嵌 WebView 打开官方登录页 → `CookieManager.getCookie(url)` 回填 → 本地校验一次 `member` 接口确认有效 |
| **Token 类** | 阿里（refresh_token）、迅雷、光鸭 | 表单粘贴（页面给操作路径提示）+ 可选"扫码/设备码"流程 |
| **账密类** | 123、天翼 | 账号 + 密码 → 调官方登录接口换会话（**密码不落盘，只落会话**） |

> WebView 登录是这里最省事也最稳的一条路：TVBox 让用户自己从电脑浏览器抓 cookie 贴进去，
> 对手机用户门槛太高。WebView 登录后 Cookie 由系统 CookieManager 管理，我们只取一次快照。

### 7.3 存储：`data/pan/DriveStore.kt`

- 落 `EncryptedSharedPreferences` 等价物；**minSdk 21 不能用 `androidx.security:security-crypto`（需 23）**，
  所以用 `AndroidKeyStore` 的 AES/GCM（API 23+），API 21/22 退化为 `MODE_PRIVATE` 明文并标注。
- key 形如 `quark.cookie` / `uc.cookie` / `uc.token` / `ali.refresh_token` …（与 TVBox 的
  `quark_cookie.txt` 一一对应，便于对照排错）。
- **`NetLog` 必须对 `Set-Cookie` / `Cookie` / `Authorization` / `dltoken` 脱敏** ——
  否则调试日志会直接把用户网盘凭据写进日志文件。

### 7.4 未登录时的行为

点集 → `resolve()` 返回 `MediaSource.Error("未登录夸克网盘")` → 现有链路是 `toast`。
**增强（小改动）**：新增 `MediaSource.NeedLogin(type)`，`PlayerActivity_Play.kt:427` 那个
`when` 加一个分支 → 弹「去登录」直接跳转网盘账号页。比 toast 好用得多。

## 8. 播放接入点：改在 `resolve()` 最前面

`SiteAdapter.resolve()`（`SiteAdapter.kt:111`）当前第一件事是 `Media.isDirect(u)`。
插入一层**自门控**分支：

```kotlin
open suspend fun resolve(episode: Episode): MediaSource {
    val u = episode.url.trim()
    if (u.isEmpty()) return MediaSource.Error("播放地址为空")

    // ★ 新增：网盘分享链接（与站型无关，PanLink 是纯函数 ⇒ 非网盘链接零开销）
    PanLink.parse(u)?.let { return PanResolver.resolve(it) }

    if (Media.isDirect(u)) return MediaSource.Direct(Media.encodeUrl(u), playHeaders(), Media.isHls(u))
    …原链路一字不改…
}
```

**三条设计理由**

1. **放最前面**：网盘分享链接长得不像媒体文件，`Media.isDirect` 一定返回 false，
   会白走一轮 HTML 抠地址 + 嗅探，最后弹 WebView 也播不了。必须先截住。
2. **自门控**：`PanLink.parse` 是纯正则、无 IO、无网盘名匹配就返回 null ⇒ 对现有所有站点零成本。
3. **`PanResolver` 内部分流**：`Episode.url` 是分享链接 → 直接展开；`Episode.url` 是
   `pan://quark/{id}/{fid}` 这种内部引用 → 按引用取流。两种都从同一个入口进。

**播放地址的形态问题**：网盘直链常常**不带扩展名**（`…/file/download?fid=…`），
而 `buildMediaItem()`（`PlayerActivity_Media.kt:161`）用 `MediaItem.fromUri`，
media3 的 `DefaultMediaSourceFactory` 靠 URI 后缀 + `mimeType` 推断内容类型 ——
后缀推断不出来时会走 progressive，HLS 就会失败。

⇒ 给 `MediaSource.Direct` 加一个 `mimeType: String? = null` 字段，在 `buildMediaItem` 里
`b.setMimeType(mimeType)`。**这是本次唯一的播放器侧改动，约 5 行**。
（备选方案是本地代理伪造 `.mp4`/`.m3u8` 后缀，但那要顺带处理播放列表内的分片地址重写，
留到 P2 一起做，见 §10。）

## 11. 风险与纪律

| 风险 | 处置 |
|---|---|
| 网盘 API 是私有接口，随时变 | 每个 Provider 独立降级：失败返回 `MediaSource.Error("夸克解析失败：…")`，绝不崩、绝不静默；错误文案要能区分「未登录」/「链接失效」/「接口变了」 |
| 站点域名秒级轮换（已实测 302 到 IP） | 判据只用形状/能力自证，**任何地方都不许出现域名白名单** |
| 直链带时效 | 绝不落盘；`ListCache`/配方/`RecipeStore` 都不碰直链 |
| 分享站会挂 | 挂的是「站」不是「能力」：③ 网盘层独立，用户直接粘分享链接照样能播 |
| Cloudflare 混淆（玩偶站已实测有 `-text/javascript` 属性） | 已有 `WebView` 预渲染兜底（`supportsWebRender`）；`PanShareAdapter` 继承它，被 CF 拦时可切 WebView 取 DOM |
| 调试日志泄露凭据 | `NetLog` 脱敏；自检/诊断输出里打印 cookie 一律 `***` |
| R8 混淆 | 新增的 Gson 模型（若有）必须进 `-keep`（E30 的教训）；优先用 `JSONObject` 手解，避免新增模型类 |
| 合规 | 只做「公开分享链接 + 用户自己登录的账号」的播放；不内置任何凭据、不做批量转存/爬取 |

## 12. 验收清单（可执行）
