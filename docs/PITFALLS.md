# 视频壳 · 踩坑总览与「通配性」清单

> 1.0.0 → 1.0.38 期间被真实站点打出来的坑，按**错在哪一层**归类。
> 每条都写成四段：**现象 → 当时的错误归因 → 真因 → 沉淀下来的通用机制**。
> 目的不是记录历史，而是让**下一个新站**少走一遍这些路。
>
> 维护纪律：新增一条坑时必须写清"通用机制"那一栏 —— 只描述现象、不给出机制的条目，
> 下一个人还会再踩一次。

---

## 0. 一句话结论

三十多个版本里，真正反复咬人的只有**一句话**：

> **能用"量"去判的，就不要用"形状"去判；能"当场测量"的，就不要"写死"，
> 也不要指望用户去手工校准。**

以及配套的三条方法论：**对照组**（错误的输入也应该出零结果）、**分层汇报**
（原始字节 vs 处理后字节）、**判据只有一份**（界面当场数出来的数 == 运行时判的数）。

## 1. 坑位总表（速查）

| N5 | 加了诊断信息后**故障更严重** | 往 HTTP 响应头塞中文 ⇒ 每请求都抛异常 | 诊断走日志，绝不进响应头 |

| C7 | 「点了对的分类，界面却说没识别到」 | **同一件事两套判据**：点击定性漏了尾斜杠家族，学习者却认它 | 「点击定性」必须 = 「学习者判据」 |

| D8 | 「第3集」被排到第 1 位 | 排序**逐条**回退：A 集取自集名、B 集取自地址，两个量级不可比 | 一列数字必须来自**同一个来源** |
| E7 | 集号判据抄了三份，各错一格 | 三处各写一遍"从标题取集号" | 判据只有一份：写一处，三处引用 |
| E8 | 同一个域名被重复添加成两条站源 | 判"在不在库里"用了 **key**（key 取决于当时的识别结果） | 「是不是同一个站」按 **host** 归一 |
| E9 | 用户选过的选项被静默换成另一个 | 持久化存了枚举**下标**，枚举插项后含义漂移 | 存**名字**，认不出就回默认 |
| S5 | 「全站源」搜出来的某一条点开是空的 | 影片 id 是**站点内**编号，聚合结果没带来源站 | 聚合结果**逐条带来源站**（从哪来、回哪去） |
| S6 | 「全站都没有这部片」其实是某站挂了 | 汇总只说"没有结果"，不说**几个站失败** | 失败要留痕并显示（N/M 个站有结果） |
| S7 | 全网搜索想抓搜索引擎结果页来解析 | 抓搜索引擎 = 把"站点适配问题"换成"搜索引擎适配问题" | **当网页打开**，我们只做"在网页上做我们擅长的事" |
| C9 | 从网页里点「手动校准」被静默弹回 | 校准页第一件事是 `Store.find(key)`，库里没有就 `finish()` | 入口动作前先把**依赖准备好**（ensureSite） |
| C10 | 逛网页时被替自己跳进了播放器 | 嗅探页只有"播放页"一种用法，浏览也被当成播放页 | 同一页面的两种用法要**显式区分**（browse 标志） |

## 2. 四处最值得说清的坑（通用化是怎么想出来的）

### ★ 坑 N1 / N4 —— 「自检单张通、界面空白」与「我的自检在骗我」

**现象**：列表 20/20 条都有封面绝对地址，DNS 正常，HTTP 200，字节数 68720 B
（很像一张正常图），**界面一片空白**。

**错误归因（连续两轮）**：
1. 第一轮归到"设备侧 DNS 污染"；
2. 第二轮归到"DoH 往返太多导致超时"。

**真因**：把字节摊开看——前四字节 `3E AA 70 8E`（不是 `FF D8 FF`），
熵 7.96 bits/byte、256 个字节值全部出现 ⇒ **这是密文**。站点图床存的就是
AES-128-CBC/PKCS7 密文，前端拿到 `arrayBuffer` 自己解密再显示。
密钥就明文躺在它自己的打包产物里，与接口那组 key/iv **不是同一组**。

**通用机制**：
- 判据从"状态码"升级为**"魔数"**（照抄站点前端那六条：JPEG/PNG/GIF/BMP/TIFF/WEBP）；
- 解密放在 **OkHttp 拦截器**里，挂在应用共用的那个 client 上 ⇒ 列表 / 详情 / 历史 /
  未来任何新封面位**一处修好**；
- 三道门控保证零成本、零回归：白名单外直接放行 → `206` 分片放行 → 已是 `image/*` 放行；
- **白名单按图床域名匹配，不按站点域名**（该站换过 3 次站点域名，图床域名一直没变）。

**顺带踩出来的 N4**：修完之后自检报告里出现自相矛盾的两句话——
`[3a]` 写"图床改回明文了"，同一份报告的 HTTP 记录写"已解密 65472→65471B"。
因为 `[3a]` 用的取图函数**挂在带解密拦截器的 client 上**，拿到的**永远已经是明文**，
它根本无从判断图床是否改回。⇒ 新增"绕过解密层"的原样取字节函数，
报告改成**分层并列**（① CDN 原样 ② 应用链路），再给四态判定。

> **可迁移的教训**：链路上每挂一个"改写层"，诊断能力就下降一层。
> 凡是需要判断"原始输入长什么样"的地方，都必须有一条**绕过改写层**的旁路。

### ★ 坑 P3 / P4 —— 「形状永远列举不完，数量永远分得开」

**现象**：用户在调试校准第 1 步点了一个分类，走完四步，提示"已完成"，
但用起来**跟没校准一模一样**。

**真因**：他点的是**侧栏导航项** `<a href="/explore/drama/">探索分类</a>`。
反推形状的函数把末段当成可变别名，老老实实泛化成 `/explore/{slug}/` ——
而站点真分类是 `/tag/{slug}/`，**两者形状完全一样**。
运行时判据要求"同一形状至少命中 2 条"，首页 330 个 `<a>` 里
前者只有 **1 条**、后者有 **252 条** ⇒ 判据正确地挡下了垃圾，
但**用户看不到任何原因**。

**通用机制（两层）**：
1. **校准当场自证**：校准界面在那一刻就调用**运行时同一个收集器**数一遍，
   命中 0/1 ⇒ 直接拒收并告诉用户"你点的是一个导航项，回去点真正的那串分类标签"。
   `-1`（数不出来）**绝不拒收**，避免误杀。拒收走"没学到"语义 ⇒ **保留旧配方**
   （点错一次 ≠ 本站没分类）。
2. **形状普查（v1.0.34）**：把这套"归纳形状 + 计数"从校准界面推广到**运行时自动**，
   与站点用什么 CMS、目录名叫什么完全无关 —— 新站不必校准也能拿到分类栏。

   它在真实首页上普查出 4 种形状，**两道阈值各挡下一类错**（这是最好的验证）：

   | 形状 | 命中 | 不同别名 | 不同名字 | 判定 |
   |---|---|---|---|---|
   | `/tag/{slug}/` | 248 | **88** | **88** | ✅ 真分类目录 |
   | `/rank/{slug}/` | 2 | **1** | 2 | ❌ 被「别名 ≥2」挡下 |
   | `/drama/{slug}/` | 5 | 5 | **1** | ❌ 被「名字 ≥2」挡下（全是「查看更多」） |
   | `/explore/{slug}/` | 1 | 1 | 1 | ❌ 两道都不过 |

   注意后两行：`/drama/{slug}/` 别名有 5 个（别名那一道过不了它），`/rank/{slug}/` 名字有 2 个
   （名字那一道过不了它）—— **两道阈值都是承重的**，少一道就会漏进一类垃圾。

> **可迁移的教训**："同形不同义"的判据突破口永远是**集合级统计量**（多少个不同别名、
> 多少个不同名字），不是更精细的形状正则。

### ★ 坑 S1 —— 「对照组」：能出结果不是证据

**现象**：**搜什么都一样**。

**当时的错误归因**：以为是解析不稳、候选模板打歪。

**真因**：站点的 `/?s={kw}` 是**软 404，直接把首页原样吐回来**。
实测连 `zzzq不存在的词` 都返回**与首页 sha256 完全相同**的页面（246747 B），
而首页自带的 58 条详情链接里恰好有 3 条含「庆余年」——
于是"严格遍"（要求结果标题含关键词）判定命中，把**首页推荐位**当成了搜索结果，
还把这条地址**固化进配方**。所有常规判据（状态码 / 条数 / 详情链接数）**全是绿的**。

**差点犯的第二个错**：我一度写下"自动学到的模板才是对的（出 58 条）"——
那 58 条是首页自己的推荐位。**是对照组把它扭回来的。**

**通用机制**：
- 守卫 `SoftMiss`：任何"结果页"与**首页签名**（长度 + 标题 + 唯一链接集合哈希）
  相同或近乎相同 ⇒ 判定为首页副本，丢弃；
- 自检 `[2b] 搜索路由自证（对照组）`：拿同一个模板发**两次**请求
  （一个像样的关键词 + 一个不可能存在的词），比两份响应是否同一个页面。
  两个方向都不会错：一致 ⇒ 路由忽略关键词；对照词零条目而真词有条目 ⇒ 路由正常。
  这对客户端渲染页同样成立（两次都是同一个空壳 ⇒ 也判"不可用"，而那是事实）。

> **可迁移的教训**：**"能出结果"不是证据，"错误的输入也应该出零结果"才是。**
> 任何一个"是否可用"的判据，都要问一句：**它在错误的前提下会不会也返回成功？**

### ★ 坑 E2 / E4 —— 排查纪律本身也是坑

- **E2**：改了代码但"没生效"的第一嫌疑是**改动根本没落盘**。
  实测踩过两次：同一回合对同一文件发多个编辑，**后面的被静默丢掉**，
  表现完美伪装成"断言写错了"。
  ⇒ 硬纪律：**一个文件一次只发一个编辑**，改完立刻用 grep 数命中数。
- **E4**：守卫断言 FAIL 时**先怀疑断言**。实测：为了讲清"上一版错在哪"而在
  **注释**里引用了旧的错误文案，`contains` 判据于是把注释算成回归
  —— 等于逼人删掉注释。
  ⇒ 守卫要判的是"**会不会打印出去**"，只看输出行，不看注释。
- **E5**：一条准备发布的探针被**撤销**了 —— 它的判据（数服务端渲染的结果链接）
  对客户端渲染页**两个方向都会错**（把首页噪声数成"可用"、把正常空壳数成"无效"）。
  ⇒ 判定一条判据能不能用，要看它**错的方向有几边**；两边都错的判据比没判据更糟。
  撤销时要留注释 + 守卫断言，防止复活。

## 3. 新站接入自检清单（照着做即可）

接到一个**新站点**时，按这个顺序走；每一步都对应上面某个坑。

### 3.1 先看它属于哪一类（决定后面所有动作）

- [ ] 抓首页，看有没有 `vodshow` / `player_aaaa` / `maccms` 指纹 ⇒ 采集接口站
- [ ] 抓接口，看响应体是不是 JSON 里的一个 base64 字段 ⇒ **加密接口站**
- [ ] 两者都不像 ⇒ HTML 站，走通用适配

### 3.2 HTML 站：先量，再判

- [ ] 分类：跑**形状普查**，看它提出的形状与计数（别名数 / 名字数是否都 ≥2）
- [ ] 详情：从列表页真实链接**反推**形状，别信穷举模板
- [ ] 分集：优先按**语义容器**找（`episode` / `playlist` / `选集`），
      容器名是全球通用的英文词，比 URL 形状稳
- [ ] 搜索：先跑**对照组自证**（真关键词 vs 不可能存在的词），再决定用哪条路由
- [ ] SSR 站：检查 `__NUXT_DATA__` / `__NEXT_DATA__` / `__INITIAL_STATE__`，
      按**元素形态**挑数组（不要按键名）
- [ ] 首页是客户端渲染的（卡片名是「查看更多」、图是 `data:` 占位）⇒ 换数据源，
      不要试图改选择器

### 3.3 图片与封面

- [ ] 整段取一张封面，**看前四字节**（不是看状态码）
- [ ] 不是图片魔数？⇒ 先查 `Content-Type`：`*octet-stream` + 图片路径 = 加密图床
- [ ] 加密图床 ⇒ 去站点自己的前端 bundle 里找 `key` / `iv` / `media_key` / `media_iv`
      字面量（**接口那组与图片那组通常不是同一组**），加一条配方
- [ ] 配方按**图床域名**匹配，不要按站点域名（站点会换域名，图床不会）

### 3.4 播放

### 4.1 新坑：**会轮换的东西不能当身份**

这一轮最贵的一条。野果（yeguodj 家族）把前端域名从 `yeguodj.com` 换到
`capable.fzchosdi.cc`、再换到 `agenda.fzchosdi.cc`，而白名单只列了 `yeguodj` 系
⇒ 不命中 ⇒ 悄悄退回 HTML 适配 ⇒ 而这一族**搜索只在接口里**（SSR 页面没有结果节点）
⇒ 用户看到「App 搜不到，但网页端能搜」。

三条教训：

- **会变的东西不能当判据**：域名、路径、压缩后的分包文件名、外层 JSON 形状、HTTP 状态码
  （站方对未知路径也回 200）都可能变。能自证的才可以：**「解得开」**。
- **站点可能在自己域名上反代了接口**：`{origin}/api.php/...` 实测与官方线路返回同一信封。
  所以 apiBase 要**从当前 origin 推导**，站点换域名自动跟上。
- **验过的姿势必须等于跑的姿势**：自证时带 `HANDSHAKE` 参数，运行时也得带，
  哪怕服务端根本不校验。否则"验过"这两个字没有意义。

### 4.2 更贵的坑：**自证候选里不能用"别人的域名"**

把"官方线路"（`www.yeguodj.com` 等）放进自证候选里，本意是"站点没反代时的退路"。
**那是把两件事混成了一件**：白名单站点的**取数**基址（已知是本族，找一个连得上的入口），
和未知域名的**血缘自证**（现场判定"这个站到底是不是本族"）。

实测（`_yg_family_probe.py`）——**官方线今天仍然解得开**：

| 候选 | 结果 |
|---|---|
| `agenda.fzchosdi.cc/api.php`（对照组） | 解得开（密文 77248 B → 明文 57932 B） |
| `www.yeguodj.com` / `yeguodj.com` / `www.ygdj2.com` / `www.ygdj3.com` | **全都解得开，同一份密文** |
| `www.baidu.com/api.php`（无关站对照组） | 解不开（返回 HTML） |

⇒ 于是一个**毫不相干**的站：自己域名的 `api.php` 一试就失败 → 接着试官方线 → 解得开 →
判成"自证命中" → 被路由到加密站适配器 ⇒ **用户输入 A 站、看到的是野果的内容**。
判据本身没有假阳性（无关站解不开），**是候选列表把假阳性引进来的**。

**修法**：自证候选**只能**从本站 origin 推导 ⇒ 判据收紧成"**本站自己**提供本族接口"，
"是我族"和"数据从哪来"才是同一句话。站点没反代 `api.php` 时退化成"判不出来 → 走网页解析"（漏收），
这是刻意接受的代价 —— 与「错收比漏收严重」同一条取舍。

### 4.3 附带的坑：**大重写会静默丢掉既有规则**

`AdapterFactory.create()` 这一轮被重写成五步流水线，**漏掉了 v1.0.15 定下的
「人工校准过（`calibAt > 0`）⇒ 优先于 apiMode」**。代码里那段注释还写着"校准优先于兜底"，
可相邻代码里根本没有这个判断 —— **注释在描述一个已经不存在的行为**。

是 `runbs4` 的行为断言（"校准过的同一站点 ⇒ 走网页解析"）当场抓住的，不然就发出去了。

两条纪律：

- **重写 = 重新证明**：既有规则的断言必须能**区分**"改结构"和"删行为"。
  所以断言要落在**行为**上（`worksAs(create(site), HtmlAdapter.class)`），
  而不是源码字面量 —— 源码守卫只能证明"这行还在"，证明不了"它还被执行"。
- **注释不能当证据**：注释说"优先于一切"，代码里没有这个分支 ⇒ 读代码时要按**代码**判断，
  发现不一致就当场补断言（而不是相信注释）。

### 4.4 新坑：**同一件事两套判据**（「点了对的分类，界面却说没识别到」）

用户原话：**「校准时，每一步点了对应的位置后，校准流程中有可能提示没识别到」**。

`SiteCalib.isCategoryShape(href)` 是**点击定性**用的判据（决定界面说"已选中"还是
"⚠ 这不像标准分类链接"）；`HtmlTemplates.catTplFrom(url)` 是**学习者**用的判据
（决定能学到什么形状）。两者必须说的是同一件事，而尾斜杠家族（`/tag/{slug}/`）
从 v1.0.32 起就是正式的分类形状家族 —— `catTplFrom` 分流认它、
`HtmlAdapter.collectSlashDirCategories` 按它收，**只有 `isCategoryShape` 没跟上**。

于是野果的真分类 `/tag/熟女/`：点击当下报「⚠ 这不像标准分类链接，形状没学到」，
按「确定」之后**又学得好好的**，报出形状 `/tag/{slug}/`。用户看到的是自相矛盾的两句话，
自然会来报"没识别到"。

同一类的第二处：`classify(Step.PLAY)` 用 `isPlayLink`（宽），而学习者
`playTplFrom` 只认 maccms 的 `/{目录}/{id}-{sid}-{nid}.html`。自研站的
`/drama/video/3381/ep-4/` 属于"说 GOOD、又学不到"—— 而运行时
`learnPlayTpl` 明明还有第二条路（`tplFromNumericSegment`）。

**修法**：让「点击定性」的判据与「学习者」的判据**同源**（学习路径全部复用运行时那两条函数），
并且把三种结论**分开说**：

| 结论 | 什么时候 | 文案 |
|---|---|---|
| 学到了 | 学习者真的产出了模板 | 「形状 /tag/{slug}/」 |
| **不需要学** | 站点自带判据本来就能认（maccms 的数字分类 id） | 「形状：站点自带判据已认得」 |
| 没学到（但兜底在） | 形状归纳不出来 | 「形状未识别」+ **具名**写出兜底是什么（容器 / 探嗅 / 详情页分集） |

第三行是关键：**「没学到」必须跟着"那靠什么"**。只说"未识别"就是把问题丢回给用户。

### 4.5 新坑：**每条失败路径都必须有终点**（第 4 步填了词点确定，流程不结束）

搜索校准（第 4 步）的地址是从「当前页 URL」里反推模板的。而对 SPA 站点，
站内搜索**不换页**（AJAX / `history.pushState`）——
`pushState` **不触发** `onPageFinished`，于是 `pageUrl` 一直停在很久以前那个首页上，
模板永远学不到；学不到时代码只是改一行状态文本就 `return`，**停在原地**。
唯一能往下走的按钮写着「取消」—— 没人会把「取消」理解成"跳过搜索校准、把前三步固化掉并完成"。

三处修法，缺一不可：

1. **地址取实时的**：`binding.webView.url`（`pushState` 后也会更新）+ JS 每次点击上报的
   `location.href` 都收下来，别只信 `pageUrl`；
2. **按钮文案 = 它实际做的事**：负按钮改成「跳过（直接完成）」；
3. **失败路径给一个必达终点的选择框**：`跳过并完成` / `我再去搜一次` ——
   两条路都能离开这一步。

通用纪律：**写流程时，把每一条 `return` 都问一遍"用户接下来怎么走出去"**。
只改状态文本的 `return`，在多步流程里等于卡死。

### 4.6 新坑：**一列数字必须来自同一个来源**（「第3集」被排到第 1 位）

野果的分集名是「**{剧名} 第N集**」，而且是**中文数字**（`少妇白洁 第二十一集`）。
集号判据只认阿拉伯数字 ⇒ 整列取不到号 ⇒ `EpisodeOrder` 的**逐条**回退生效：
A 集的号来自集名（`…第3集` → 3）、B 集的号来自伪地址（`yeguo://play/2275/186514` → 186514）。
两个量级根本不可比，`我能看到欲望值` 的第 3 集**被排到了第 1 位**。

逐条回退（"这条取不到就换下一个来源"）放在**排序 / 编号**里一定是错的 ——
只要同一列里混进两个来源，就有两把不同的尺子。正确写法是**整列同源**：

1. 整列都能从集名取到号且互不相同 ⇒ 用集名；
2. 否则整列试站点序号（`index` / `sort`）；
3. 否则整列用数组位置。

附带一条：`noOf()` 那个"名字取不到就退到地址"的兜底让「有任何一个取不出集号就不猜」
这道闸门**从来没关上过**（伪地址里天然有数字）—— 所以闸门必须判在**同一个来源**上。

### 4.7 新坑：**判据抄三份 = 三类站点各错一格**

"从标题里读集号"这件事，代码里原本有**三份**：
`EpisodeOrder.NAME_PATTERNS[0]`、`SsrPayload.TITLE_NO`、`YeguoMap` 里新写的一份。
三份都只认阿拉伯数字，于是：

- 野果（API 路径）整列取不到号 ⇒ 显示成剧名 + 排序错位；
- SSR 路径遇到中文数字集名时 `useTitle` 静默为 `false`，退到 `sort` ——
  而 **SSR payload 的 `sort` 恒为 1**（本文件当年就实测记下过），名字会全变成「第1集」。

已合并成 `EpisodeOrder.noInTitle`（阿拉伯 + 中文数字 + `第N{集话期回部}` 形状），三处引用。
**形状也必须保留**：`《庆余年》 第三季第一集` 里有「三」有「一」，只有形状能定出 1；
`AI短剧 窥破爱人谎言2` 末尾那个 `2` 是剧名的一部分，**不许**当集号。

合并它的理由不是"更整齐"，而是**三份副本的差异 = 三条不同的错误路径**。
遇到"这段逻辑好像在哪见过"时，先去找到那一份。

### 4.8 一条自查：**「拒收」要说清为什么不写**

`pickCategory` 在形状被拒收时**连容器一起不收**（v1.0.34 的实测：从同一次导航项点击
推出来的容器只是 `div.app-layout` 页面外壳，收下它会让 `manualNavSel` 把好用的默认判据顶掉）。
这本身是对的取舍 —— 但界面原来只说"改点真正的那一串分类标签"，
用户不知道**本次什么都没写**，也不知旧规则还在不在。

本轮改成明说：「本次**不写入任何分类规则**（写了反而会把上一次学对的规则挡掉）」。
**"什么都没发生"是最容易被误解成"坏了"的结果**，必须自己解释。

### 4.9 新坑：**判断"是不是同一个站"要用 host，不能用我们自己生成的 key**（v1.0.37）

「在网页里一键识别并添加」与「手动校准」是同一件事的两个入口，它们都先要回答
一个问题：**这个站在不在库里？**

原来的写法是问 `Store.find(key)`。而 `key` 是**我们自己的产物**，它取决于"当时识别成了什么"：

| 识别结果 | key |
|---|---|
| 有采集接口 | `base + 接口路径 + 参数` |
| 网页适配 | `base` |
| 自证成加密接口族 | 又可能换一种 |

于是同一个域名，用 key 问就会得到**"不在库里"** ⇒ 再添加一遍 ⇒ 站点列表里出现
两条指向同一个站的记录。用户的原话会是「我明明加过了，怎么又出来一个」。

**通用机制**：凡是"这是不是同一个东西"，判据必须建立在**对方的、稳定的**属性上
（这里是 host），而不是我们自己派生的标识（key 会随我们的识别路径变化）。
和 §4.1「会轮换的东西不能当身份」是同一条纪律的另一面 ——
**能被我们自己的流程改动的东西，也不能当身份**。

配套：`Store.hostOf` 是唯一的 host 提取器（`RecipeStore.hostOf` 的转发 + 裸 host 兜底），
`WebSiteKit.hostOfBase` 再做 `www.` 归一 —— 因为用户从搜索结果点进来是
`https://www.x.com/...`，而当初识别时存的是 `http://x.com`。

### 4.10 新坑：**持久化存名字，不存下标**（v1.0.37）

搜索范围（本站/全站/全网）要记住用户上次选的哪个。存 `ordinal` 看着最省事，
但它有一个**只在将来才发作**的缺陷：枚举里插一项（比如以后加「搜指定站」），
老用户的 `1` 就从"全站"变成了另一个东西 —— 用户什么都没点，选项自己变了。

**通用机制**：凡是"用户选过的枚举"，一律存 `name()`，读的时候用
"认得出就用、认不出回默认"的方式解析（`SearchScope.of`），**绝不做下标换算**。
断言里专门钉了 `of("1") → SITE`，就是防止有人"顺手"把下标解析加回来。

### 4.11 新坑：**同一个页面的两种用法，必须显式区分**（v1.0.37）

「网页嗅探模式」原来的唯一用法是**播放这一页**：认得出的正片就自动跳播放器。
现在它还要当**浏览器**用（搜全网 → 点开结果 → 逛到影片站）。
两者共用同一个 Activity、同一个 WebView、同一套候选收集，**唯一不能共用的就是"自动播"**：

- 播放用法：用户点进来就是为了播，自动播是省事；
- 浏览用法：用户点进来的每一下都是他自己的意图，替他跳走等于把他打断在自己不知道的地方。

所以加了一个 `browse` 标志，`maybeProbeAndAutoPlay()` 开头一句 `if (browse) return`。
配套三处也必须跟着分叉，否则会留下"看起来像坏了"的地方：
状态文案（不报"超时/登录墙"，因为用户不是在等嗅探）、
`MAX_TICKS` 轮询上限（浏览没有"超时"这回事）、
以及顶部返回键的语义（浏览时是"网页后退"，退无可退才关闭）。

**通用机制**：给一个已有界面加第二种用法时，先列出"它现在为第一种用法**默认**做了哪些事"，
逐条决定第二种用法要不要 —— 少改一条，用户就会在第二种用法里撞上第一种用法的贴心。

### 4.12 一条刻意的取舍：**不抓搜索引擎的结果页**

「搜全网」最直觉的实现是：把 Bing 的结果页 GET 回来，解析出链接，做成我们自己的卡片列表。
**我们不做这件事**，直接把结果页当网页打开。理由是成本结构：

| | 抓取解析 | 当网页打开 |
|---|---|---|
| 依赖 | 搜索引擎的 HTML 结构 | 只要浏览器能打开 |
| 对方改版 | **我们必挂**，且要等发版 | 零影响 |
| 反爬 / 跳转 / 同意页 | 每一个都是我们要处理的 | 交给浏览器 |
| 用户能做的下一步 | 只能点我们解析出来的 | 能点、能翻页、能再搜，还能「识别并添加」 |

这跟 §0 的结论一致：**我们擅长的是"在任意网页上做识别与嗅探"，不是"复刻别人的页面结构"。**
把不擅长的部分换成"把网页交给用户 + 把我们擅长的按钮摆在他手边"，这条线才不用年年修。

断言里为此钉了两条：`SearchScope` 里**不出现** `Jsoup` / `Http`（守卫不抓取），
以及 `isWebHost` 的**双边**判据（`notbing.com`、`bing.com.evil.cn` 都必须为 false）。

### 4.13 新坑：**断言辅助函数把「期望」和「实测」印反了 ⇒ 我会去改没坏的那一侧**（v1.0.38）

写 Java 离线断言时 `eq` 长这样：

```java
static void eq(String name, Object got, Object want) {           // ← 参数名是 (got, want)
    ok(name, Objects.equals(got, want), "got=" + got + " want=" + want);
}
```

而所有调用点都按直觉写成 `eq("标题", 期望值, 实测值)`。两件事叠在一起：

1. `Objects.equals` 是**对称**的 ⇒ 判定结果完全不受影响，162/164 条照样 PASS。
   **参数顺序错了不会红**，所以这个错误可以潜伏很久。
2. 但报错文案是 `got=` + 第 2 个实参、`want=` + 第 3 个实参 ⇒ **印出来正好颠倒**。

于是那 1 条真红的输出是：

```
[FAIL] 全都在时，最后一个站插在末尾    → got=6 want=4
```

我读成「代码返回 6，我期望 4 写错了」，就把字面量从 `4` 改成了 `6`。
**改完仍然红，因为真相是反的**：`insertAt` 返回的是 `4`（=前面两块 3+1 之和，不含自己），
`4` 从一开始就是对的，是我的"修复"把它弄坏了。

**教训一句话：报错的措辞和报错的数值一样要当判据看。**
`got=` / `want=` 一旦颠倒，"哪一侧错了"这个最基本的判断就是反的 ——
而它恰好指给你一个**编译器不会拦、测试也可能不红**的方向。

落地动作（两条都要做）：

- `eq` 参数名与打印顺序对齐成 `(name, want, got)`，文案改成 `want=… got=…`，
  并在函数上方写明「调用点统一写 `eq(标题, 期望, 实测)`」——**注释解释的是"为什么不能改回去"**。
- 判据本身钉注释：那个断言的值是 `3+1=4`（**只数排在它前面的已到达块**），
  顺带把标题写全（「= 前面两块之和 3+1，不含自己」），防止下次又有人"顺手修正"成 6。

这与 §2 的 E2/E4 是同一族坑，但更阴：E2/E4 是**守卫写错**（red 时先怀疑守卫），
这条是**守卫的"读数"错**（红的时候连"谁红"都读反了）。凡是"打印给人看"的辅助函数
（`eq`/`ok`/`banner`/自检汇报），都要有**断言级的自证**，或者至少让文案与调用点顺序一致。

### 4.14 新坑：**量错对象 = 结论无效**（"看起来的第一条分片"不是播放器会取的那条）（v1.0.39）

用户报「枫叶影院很多播放源能读到时長、一直转圈」。第一轮探针很"干净"：

```
段[0] status=200 ctype=video/mp2t magic=474011…
段[1] status=200 …  段[2] status=200 …
```

于是得出"分片都正常，不是分片的问题"。**这个结论是错的**，因为 `segs[0..5]` 取的是
**广告段**：清单开头就是 8 条 `/ad/XNjU1…/…-00001.ts`，而 `HlsPlaylistFixer`
把它们**整块剔掉**了 —— ExoPlayer 实际从那之后的第一条**正片**段开始取。

**教训一句话：量之前先算清"被测对象到底是哪一条"。**
判据（`/ad/` 正则 + 跟着剔 `DISCONTINUITY`）本来就在我们自己代码里，
复刻一遍只要十行，却能避免整个诊断走错方向。落地：`runzqseg.py` 现在按
**HlsPlaylistFixer 的同一套判据**算出保留序列，体检的是 `kept[0]`。

顺带钉住一条**反向**断言：剔广告后必须仍剩 ≥30 条正片段 ——
否则说明广告正则吃掉了正片，那才是**我们自己造出来的"播不了"**。

### 4.15 新坑：**瞬时失败和终态失败必须分开判**（402 不是"要付款"，是限流信号）（v1.0.39）

实测：`cibn-edge-5g.1ljx.com`（Vercel 边缘）对**成片的分片请求**回
`HTTP 402 Payment Required`，而**清单始终 200**。停 90 秒再取，全好了。

这就是"时长读得到（清单早就到手）、画面一直转圈（分片取不到）"最直白的一种成因。
而 ExoPlayer 自带的加载策略把 4xx 当**内容的错**（404 明确不重试）⇒ 一个**会自己好**的
故障被它当成了终态。

落地：`PlayRetry`（纯对象，可离线断言）+ 在 `OkHttpDataSource.open()` 里就地退避重试。
两条硬约束值得写下来：

1. **`402` 必须在瞬时表里**，`403/404/410` 必须**不在** —— 后者重试只会白等，
   还会把"该换源"的情况拖成一段没有信息的转圈。
2. **最坏代价必须有界**（这里 0.6s + 1.5s = 2.1s，断言钉死 `< 3s`）。
   用"等 90 秒再试"去修"一直转圈"是把瞬时故障变成用户眼里的"这软件坏了"。

### 4.16 新坑：**重试"同一个地址"≠"重新解析"**（令牌是按会话发的）（v1.0.39）

枫叶影院 ps:1 线路的播放地址是**播放时现取**的：外壳页 `POST mplayer.php` 返回
`…m3u8?auth_key=<时间戳>-…`，清单里的分片又带 `psid=<每次不同>`。
**每次解析拿到的令牌都不一样**。

所以卡住时把同一个 URL 再取一遍是**白费**（令牌没变），必须**重新解析本集**
（再走一次 `playEpisode` → `resolve()`）换一份新令牌 —— 这也正是用户自己会做的事
（退回详情页再点一次）。

两个反直觉的细节：

- **自愈的次数上限不能被自愈自己清零。** 自愈走的也是 `playEpisode` → `playUrl`，
  而 `playUrl` 会把 `stalledSwitched` 之类的标志复位 ⇒ 拿它当上限等于没有上限，
  一次卡住会**无限重解析**下去。所以另开一个只增不减的 `stallReResolveTries`，
  **只在用户发起的换集/换源时清零**（`playEpisode(index, autoHeal = false)`）。
  "用户动一下 = 给一次新的自愈预算"。
- **嗅探源不走这条路**：它有自己的候选队列与换源逻辑，两套自愈会互相打架。

### 4.17 一条纪律：**"转圈"这两个字里没有任何可查的东西**（v1.0.39）

卡住面板原先只说"已缓冲 X / 共 Y / 地址 = …"。这对用户和对我都等于没说 ——
分片是被拒（402/403）、超时了，还是压根没人回？三者要做的事完全不同。

落地：面板带出 `NetLog.lastFailure()`（`HTTP 402 … @ <url>`）。
**不是锦上添花**：这次问题拖了几轮，唯一原因就是每一轮拿到的都是"转圈"两个字。
凡是"用户描述里没有任何可查信息"的现象，第一件事是**把它变成一条可读的读数**。

### 4.18 一条 UI 细节：**网格里的分组标题必须独占整行**（v1.0.39）

聚合搜索按站分块，块之间要加一行"站名 + N 条"。但容器是
`GridLayoutManager`（竖屏 3 列 / 横屏 5 列）—— 不给 `SpanSizeLookup` 的话，
标题只占一格，和卡片并排，**分组边界比不加标题还糊**。

配套：适配器要暴露 `isHeader(position)`，`getSpanSize` 只认这一处判据
（别在 Activity 里再判一次 `rows[pos] is Header` —— 那是第二套判据）。

### 4.19 一条断言纪律：**不要写 vacuous 断言**（v1.0.39）

给 #1（搜索不显示分类标签）写断言时，因为渲染要真机，顺手写了两条：

```java
ok("VideoAdapter 暴露 setSearchKeyword（唯一入口）", true);
ok("hideTags 与 highlight 由同一个方法一起设 ……", true);
```

它们**永远绿、且什么都不验** —— 比没有断言更糟：报告上多两行 PASS，
读的人会以为这条已经验过了。

落地：撤掉，改成一条明确的 `[SKIP]` 说明"渲染需设备"，并把**能离线验的部分**
（一个入口、各**一个**写入点、副标题里真的按 flag 分流）全部搬进源码守卫，
那里数的是**活代码**。**能验的必须验，不能验的必须说清不能验 —— 不许用 PASS 糊过去。**

### 4.20 单位变了，不变量要在新单位里**重证**（v1.0.39）

`AggSearch.insertAt` 从"卡片数"改成"**行数**"（每块多一行标题）：
`h0(3 卡)` 的插入点从 `3` 变成 `4`。旧断言（Agg38 D 段）里那几个字面量
必须一起改，**但改数字不等于放弃断言** —— 同时在**行空间**重立同一条不变量
（任意到达顺序铺出来的网格 == 一次性 `mergeRows`），并补一条
**投影断言**：`mergeRows(...)` 的卡片投影必须逐条等于 `merge(...)`。

这样"两份判据同源"这句话才是可执行的，而不是一句注释。
**改契约时，断言要跟着换空间，不能只跟着换数字。**
